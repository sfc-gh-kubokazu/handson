## 環境の準備

`scripts/step0_setup.sql` を実行してください。

```sql
-- Snowsight のワークスペースで scripts/step0_setup.sql を開いて全実行
```

作られるもの:

| 種類 | 名前 | 用途 |
|---|---|---|
| データベース / スキーマ | `DOC_SEARCH_HANDSON.HANDSON` | 全部ここに入れます |
| ステージ | `DOCS` | PDF置き場。**SSE暗号化が必須** |
| ステージ | `STREAMLIT` | 手順4のデプロイ先 |
| テーブル | `M_PRODUCT` (8件) | 架空の糖尿病薬マスタ |
| テーブル | `M_FACILITY` (6件) | 架空の施設マスタ |
| テーブル | `M_DOCTOR` (6件) | 架空の医師マスタ |
| テーブル | `T_SALES` (144件) | 架空の月次売上（2026-01〜03） |
| テーブル | `T_EVENT_ATTENDEE_RAW` (7件) | 手順6用。表記が揺れた名簿 |
| セマンティックビュー | `SV_SALES` | ②-1の復習。手順3で使います |

**注意**: `DOCS` ステージは `ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE')` を指定しています。
既定のクライアントサイド暗号化のままだと `AI_PARSE_DOCUMENT` が読めません。
これは後から `ALTER` で変更できないので、作るときに指定してください。

**もう1つ注意**: `DOCS` は `CREATE OR REPLACE` ではなく `CREATE IF NOT EXISTS` にしています。
`OR REPLACE` にすると、このスクリプトを再実行したときに
**アップロード済みのPDFが消えます**（作成中に実際にやりました）。
すでにSSE無しで作ってしまった場合だけ、`DROP STAGE DOCS;` してから作り直してください。

### 動作確認

セマンティックビューが引けるか確認します。

```sql
SELECT * FROM SEMANTIC_VIEW(
    DOC_SEARCH_HANDSON.HANDSON.SV_SALES
    DIMENSIONS product_name
    METRICS total_amount
)
ORDER BY total_amount DESC
LIMIT 3;
```

自社製品3つが金額の多い順に出れば準備完了です。

## データについての注意

- **売上・施設・医師・製品はすべて架空**です。実在のものとは関係ありません
- **PDFはPMDAが公開している実際の文書**です（手順1で扱います）
- 製品名は架空ですが、薬効群（SGLT2阻害薬など）は実在の分類に対応させています。
  手順3で「架空の売上」と「実在文書」をつなぐために、ここだけ合わせてあります
