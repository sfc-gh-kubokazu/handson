# 手順5: CoCoから呼べるようにする（Personal Skills）

**所要時間**: 10分
**ファイル**: `scripts/step5_skills/pmda-doc-search/`

## ゴール

ここまでで作った検索を、**CoCo（Cortex Code）から自然文で呼べる**ようにします。

②-1 でスキルの作り方は扱いました。今日は
**作った資産を呼び出すスキル**という使い方をします。

```
あなた: 「ジャヌビアは腎機能障害の患者に使える？」
   ↓  （スキルが自動で起動）
CoCo:  Cortex Search を検索 → 出典付きで回答
```

## スキルとは（1分で）

- ワークスペース配下の `.snowflake/cortex/skills/<名前>/SKILL.md` に置くMarkdown
- 冒頭の `description` に書いた**トリガー語**を CoCo が見て、自動で読み込む
- 中身は「手順書」。SQLの書き方、守るべきルール、出力形式を書く

**プロンプトを毎回書く代わりに、手順を1回書いて置いておく**という発想です。

## 置き方

ワークスペースの中に次の構造で置きます。

```
.snowflake/cortex/skills/
└── pmda-doc-search/
    ├── SKILL.md
    └── references/
        └── search_queries.sql
```

`scripts/step5_skills/pmda-doc-search/` をそのままコピーしてください。

置いたら、CoCo のチャットで確認します。

```
/skills
```

`pmda-doc-search` が一覧に出れば認識されています。

## SKILL.md の読みどころ

### 1. description がトリガー

```yaml
description: "PMDA公開文書（電子添文・審議結果報告書）を Cortex Search で検索し、
出典付きで回答する。... トリガー: 添付文書, 電子添文, 添文, 禁忌, 効能, 用法用量,
副作用, 相互作用, 審査報告書, PMDA, 製品比較, この薬は."
```

**現場で使う言葉を並べる**のが要点です。
「電子添文」「添文」のような略称や、「この薬は」のような口語も入れます。
ここが弱いとスキルが起動しません。

### 2. 「絶対に守ること」を最初に書く

```markdown
1. 検索結果に書かれていないことは書かない。一般知識で補完しない。
2. 回答の各記述に出典を付ける。形式は （製品名／文書種別／Nページ）。
3. 対象は下記4文書のみ。
4. 医療上の判断や推奨はしない。文書の記載を伝えるにとどめる。
```

手順の説明より先に、**やってはいけないこと**を書きます。
順序を逆にすると守られにくくなります。

### 3. エラーと対処法を書いておく

```markdown
### 検索結果が0件
まず索引にデータが入っているかを確認します。
...
`filter` の値はマスタの表記と完全一致でなければヒットしません
（例: `ジャヌビア` ではなく `ジャヌビア錠`）。
```

**自分がハマったことを書いておく**と、次から同じところで止まりません。
スキルの価値の半分はここにあります。

### 4. 比較のときは製品ごとに検索させる

```markdown
1回の検索で全製品を均等に拾えるとは限らないため、製品ごとに検索してください。
```

44ページの審議結果報告書が上位を占めてしまう問題（手順2）への対処です。
**検索の癖を知っている人だけが書ける指示**で、こういうものがスキルに溜まっていきます。

## 試すこと

CoCo のチャットで、SQLを1行も書かずに聞いてみてください。

```
ジャヌビアは腎機能障害の患者に使える？
```

```
3剤の高齢者への投与に関する記載を比較して表にして
```

```
マンジャロの併用注意の薬剤を教えて
```

**確認するポイント**

1. スキルが起動したか（CoCoが `pmda-doc-search` を読み込んだと言うか）
2. 出典が付いているか
3. **文書に無いことを聞いたときに「記載がありません」と言うか**

3番を試してください。

```
この薬の1日の薬価はいくら？
```

## ②-1 との違い

| | ②-1 | ②-2（今日） |
|---|---|---|
| スキルの中身 | レポートのテンプレート | **検索サービスの呼び出し方** |
| 呼ぶもの | テーブル | **自分で作ったCortex Search** |
| 溜まる知識 | 集計の型 | **検索の癖と落とし穴** |

作った資産（検索サービス）と、それを使うための知識（スキル）を
セットで置いておくと、チームで共有できます。

## つまずきどころ

| 症状 | 原因 | 対処 |
|---|---|---|
| スキルが起動しない | トリガー語が足りない | description に現場の言葉を足す |
| スキルが見えない | 置き場所が違う | `.snowflake/cortex/skills/` 配下か確認 |
| 一般知識で答える | 「守ること」が弱い | 冒頭の禁止事項を強く書く |
| 参照ファイルを読まない | パスの書き方 | `skills/<名前>/references/...` と明示する |
