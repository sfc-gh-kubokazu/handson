# 手順6: 表記揺れを名寄せする（AI関数）

**所要時間**: 10分
**スクリプト**: `scripts/step6_name_matching.sql`

## 今回使うもの

| 名前 | これは何か |
|---|---|
| **`AI_SIMILARITY`** | 2つの文字列の意味的な近さを -1〜1 の数値で返す Cortex AI 関数。表記が違っても意味が近ければ高い値になる |
| **`AI_COMPLETE`** | 指定したLLMに判断させる Cortex AI 関数。ここでは「同一人物と断定してよいか」を判定させる |
| **`response_format`** | `AI_COMPLETE` の出力をJSONスキーマに従わせる指定。戻り値をそのままSQLの列として扱える |
| **`QUALIFY`** | ウィンドウ関数の結果に対して絞り込む句。「各行の上位3件」のような条件を書ける。**`GROUP BY` より後に評価される**ため、集計と組み合わせるときはサブクエリに分ける |
| **`LISTAGG`** | 複数行を1つの文字列にまとめる集計関数。候補リストをプロンプトに埋め込むのに使う |

## ゴール

講演会の参加者名簿（手入力）を、医師マスタに突き合わせます。
**SQLだけでどこまでできて、AI関数を足すと何が変わるか**を見ます。

前回「またやりましょう」と言っていた話です。単独で読めます。

## 題材

| 名簿（手入力） | マスタ（正） | 揺れの種類 |
|---|---|---|
| 斉藤健太郎 / 中央総合病院 | 齊藤 健太郎 | 姓の異体字 |
| 渡辺 美咲 / みなと大学病院 | 渡邊 美咲 / みなと大学医学部附属病院 | 異体字＋施設名の略称 |
| 高橋　淳 / さくら内科 | 髙橋 淳 / さくら内科クリニック | 異体字＋全角空白＋略称 |
| 山崎里奈 / 北山記念病院 糖尿病内科 | 山﨑 里奈 / 北山記念病院 | 異体字＋診療科付き |
| 小林大輔 / あおば糖尿病内科クリニック | 小林 大輔 / あおば糖尿病内科 | 空白＋略称 |
| 中嶋 陽子 / 西湖医療センター | 中島 陽子 | 異体字 |
| **佐藤 一郎 / 東京第一病院** | **（マスタに存在しない）** | **該当なし** |

最後の1件が入っているのが要点です。
**無理に当てはめず「該当なし」と言えるか**を見ます。

## 手順

### 6-1. 完全一致でJOINする

```sql
LEFT JOIN M_DOCTOR d ON d.doctor_name = r.attendee_name_input
```

結果: **0件一致**。

### 6-2. 空白を除去して正規化する

```sql
ON REPLACE(REPLACE(d.doctor_name,' ',''),'　','')
 = REPLACE(REPLACE(r.attendee_name_input,' ',''),'　','')
```

結果: **1件だけ一致**（小林大輔）。

異体字は依然として一致しません。
「渡辺／渡邊／渡邉」「高橋／髙橋」「崎／﨑」…の対応表を自前で持つ道もありますが、
**網羅し続けるのが現実的でない**のは想像がつくと思います。

### 6-3. AI_SIMILARITY で「近さ」を数値にする

```sql
AI_SIMILARITY(
    r.attendee_name_input || ' ' || r.facility_name_input,
    m.doctor_name || ' ' || f.facility_name
)
```

氏名だけで比べると同姓の取り違えが起きるので、**氏名＋施設名**をまとめて比べます。

上位3候補を見ると、こうなります。

| 行 | 名簿 | 1位 | 類似度 | 2位 | 類似度 |
|---|---|---|---|---|---|
| 1 | 斉藤健太郎 | 齊藤 健太郎 | 0.9379 | 髙橋 淳 | 0.6141 |
| 3 | 高橋　淳 | 髙橋 淳 | 0.9445 | 齊藤 健太郎 | 0.5724 |
| **4** | **山崎里奈** | **山﨑 里奈** | **0.7484** | **小林 大輔** | **0.7058** |
| 6 | 中嶋 陽子 | 中島 陽子 | 0.9718 | 齊藤 健太郎 | 0.5933 |

**4行目を見てください。** 1位と2位の差が 0.04 しかありません。
正解は当たっていますが、**「1位を機械的に採用する」運用にすると、
どこかで別人を紐付けます**。

ここが実務で一番危ないところです。
「AIで名寄せできました、精度98%です」という報告が、
**残り2%がどの行かを言えない**なら使えません。

### 6-4. AI_COMPLETE に判断させ、確信度と根拠も出させる

類似度は「近さ」しか教えてくれません。
**「同一人物と断定してよいか」**を判断させます。

```sql
AI_COMPLETE(
    'claude-4-sonnet',
    '...異体字（斉藤/齊藤、渡辺/渡邊...）があり、施設名も略称や診療科付きで
      入力されることがあります。氏名と施設名の両方を根拠に判断してください。
      該当する候補が無い、または判断できない場合は doctor_id を NONE に...',
    { 'response_format': { 'type': 'json', 'schema': { ... } } }
)
```

`response_format` で出力を構造化しておくと、そのままSQLで扱えます。

結果:

| 行 | 名簿 | 判定 | 確信度 | 根拠（抜粋） |
|---|---|---|---|---|
| 1 | 斉藤健太郎 | D001 | 高 | 「斉藤」と「齊藤」が異体字の関係にあり…施設名も完全一致 |
| 2 | 渡辺 美咲 | D002 | 高 | 「みなと大学病院」が「みなと大学医学部附属病院」の略称として一般的 |
| 4 | 山崎里奈 | D004 | 高 | 「崎」と「﨑」の異体字…診療科が付加されているだけ |
| **7** | **佐藤 一郎** | **NONE** | **高** | **異体字を考慮しても一致する候補がありません** |

**類似度では危なかった4行目が、根拠付きで確定しました。**
そして7行目は正しく「該当なし」。

### 6-5. 実務に落とす

```sql
CASE
    WHEN judgement:doctor_id::VARCHAR = 'NONE'
        THEN '該当なし（マスタ登録の要否を判断する）'
    WHEN judgement:confidence::VARCHAR = '高'
        THEN '自動反映してよい'
    ELSE '人間の確認が必要'
END
```

**★ここに落とし穴があります。**
7行目は「該当なし」を**確信度"高"**で返してきます。判定としては正しいのですが、
やることは自動反映ではなく「マスタに登録するかどうかの判断」です。

確信度だけで振り分けると、これを「自動反映してよい」に入れてしまいます。
**`doctor_id` を先に見る**必要があります。

結果:

| 振り分け | 件数 |
|---|---|
| 自動反映してよい | 6 |
| 該当なし（マスタ登録の要否を判断する） | 1 |

全件を人手で見るのと、危ない行だけ見るのでは工数が変わります。

## 押さえてほしいこと

1. **AI関数は毎回まったく同じ出力を返すとは限りません。**
   名寄せ結果を基幹データに直接書き戻す設計にしないでください。
   判定を別テーブルに残し、確信度で人間の確認を挟む形にします。

2. **根拠を出させることに価値があります。**
   「D004です」だけだと検証できません。
   「崎と﨑の異体字で、施設は診療科が付いているだけ」まで出れば、
   人が5秒で確認できます。

3. **「該当なし」と言えることが精度そのものです。**
   マスタに無い人を無理に紐付けるのが、この手の処理で一番怖い失敗です。

## つまずきどころ

| 症状 | 原因 | 対処 |
|---|---|---|
| `unexpected 'GROUP'` | `QUALIFY` を `GROUP BY` の前に書いた | サブクエリに分ける |
| `AI_COMPLETE` がNULLを返す | `PROMPT()` と `response_format` の併用 | 文字列連結で組み立てる |
| 判定がぶれる | 温度の揺れ | 確信度で人間の確認を挟む |
| 同姓の取り違え | 氏名だけで比較した | 施設名も連結して比較する |
